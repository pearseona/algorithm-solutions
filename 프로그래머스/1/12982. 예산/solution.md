# 예산

## 접근방식

- 신청 금액이 적은 부서부터 지원하기 위해 `d` 배열을 오름차순으로 정렬
- 배열을 순회하면서 남은 예산으로 현재 부서를 지원할 수 있는지 확인
- 예산이 부족하면 반복문을 종료
- 지원할 수 있으면 신청 금액을 예산에서 빼고 지원한 부서 수를 1 증가
- 지원한 부서 수를 반환

## 사용한 알고리즘

- 정렬과 그리디 알고리즘
- 같은 수의 부서를 지원할 때 신청 금액이 적은 부서부터 선택하면 필요한 총금액이 최소가 됨
- 따라서 적은 금액부터 차례로 지원하면 주어진 예산으로 최대한 많은 부서를 지원할 수 있음

## 시간 복잡도

- 부서 수를 n이라고 할 때, 정렬에 O(n log n)
- 지원 가능한 부서를 확인하는 순회에 O(n)
- 전체 시간 복잡도는 O(n log n)

## 학습 메모

- `Arrays.sort(d)`는 기존 배열을 오름차순으로 정렬
- `budget < d[i]`이면 현재 부서를 지원할 예산이 부족하므로 `break`로 반복문을 종료
- 정렬된 상태이므로 현재 금액을 지원할 수 없으면 뒤에 있는 금액도 지원할 수 없음
- 남은 예산과 신청 금액이 같으면 지원할 수 있으므로 `<`로 비교
- `budget -= d[i]`는 `budget = budget - d[i]`와 같은 의미
- `answer++`는 실제로 부서를 지원한 경우에만 실행
- `Arrays.sort(d)`를 사용하면 입력 배열의 순서가 변경됨
